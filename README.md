# Viper Racing Modding

A toolkit and app suite for modding *Viper Racing* (1998): parse and rebuild its
file formats, browse and 3D-preview your cars and tracks, edit their textures,
swap tracks into the game's slots, set up the AI field, add modern resolutions,
and check your install for the fixes it needs to run well on a modern PC.

Everything is built on **`vrmod`**, a self-contained Python toolkit (pure standard
library apart from `capstone`, and even that only for one optional patch). The same
`vrmod` powers two front ends:

| Front end | What it is | Where |
|---|---|---|
| **`vrmod` CLI + toolkit** | Parsers/builders for every format, plus a local web UI | [`vrmod/`](vrmod/) |
| **Viper Racing Mod Manager** | A native desktop app (pywebview) around the web UI | [`desktop/`](desktop/) |

Looking for **community mods** rather than the tools? They live at
[**viper-racing-gallery**](https://github.com/HerbFargus/viper-racing-gallery) —
2,023 cars and tracks, browsable at
[herbfargus.github.io/viper-racing-gallery](https://herbfargus.github.io/viper-racing-gallery/).

Plus documentation in [`docs/`](docs/), in three parts — readable on GitHub, or rendered with a contents page at
[**herbfargus.github.io/viper-racing-modding**](https://herbfargus.github.io/viper-racing-modding/).
The HTML is built by CI and never committed, so it cannot drift from the Markdown the way the old hand-maintained copies did.

observed in game.

> **Repo naming:** the GitHub repo is `viper-racing-modding`; the Python package is
> `vrmod`; the desktop app's product name is "Viper Racing Mod Manager". The
> **community gallery** lives in its own repo and is deliberately *not* here; this
> repo is tools only.

## Layout

```
vrmod/            the toolkit: parsers/builders, CLI, and the web UI (switcher_ui.py)
  assets/         three.min.js (bundled for offline 3D) + stock slot icons
desktop/          the standalone app: app.py, the PyInstaller spec, icon
docs/reference/   the reverse engineering: bytes, structure, runtime behaviour
docs/history/     who built the old tools, and old workflow vs new
docs/archive/     rescued community material, preserved as it was
scripts/          check suites and corpus tooling
```

Game data is **never** committed — the toolkit reads your own install, and
`.gitignore` blocks `*.car/.trk/.tra/.res`, `race.bin`, etc.

## The toolkit / CLI

`vrmod` is pure standard library apart from `capstone` (used only by the optional
`race.bin` vertex-buffer patch — imported lazily, so everything else, including the
whole viewing path, runs with no third-party dependency; that's what lets the
community gallery run it under Pyodide in the browser).

```bash
python -m vrmod.cli switcher "C:\path\to\Viper Racing\Data"
```

## The desktop app

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python desktop\app.py
```

It opens on a landing screen; choose your Viper Racing **Data** folder (the one with
`race.bin` and your `.car` files) and it remembers it next time.

### Building the standalone .exe

With the venv set up, plus PyInstaller (`pip install pyinstaller`):

```bash
.venv\Scripts\python -m PyInstaller --noconfirm desktop\viper-mod-manager.spec
```

Produces a **single file**, `dist\ViperModManager.exe` (~16 MB) — that one
file *is* the whole app. The spec bundles `vrmod/assets/` (three.js + slot icons),
capstone's native lib, pywebview's backend, and the app icon (`desktop/icon.ico`,
generated by `desktop/make_icon.py`). Paths in the spec are anchored to its own
location, so it builds from anywhere.

## Building a browsable gallery of your own

`vrmod gallery` walks a folder — any layout, stock and modded side by side — and
writes a static site: one interactive 3D page per car and per track, plus an
index linking them. No server, no hosting, no dependencies; open `index.html`
from disk.

```bash
python -m vrmod.cli gallery "C:\path\to\Data" out\gallery --serve
```

The [community gallery](https://github.com/HerbFargus/viper-racing-gallery) is
the same idea pointed at 2,023 mods instead of one install.

## The modern engine

An optional engine upgrade from the companion viper-racing-port project: a DLL placed beside the game (`dinput.dll`,
with `SDL2.dll` and `viperport.ini`) that runs Viper Racing on OpenGL and SDL instead of DirectDraw,
Direct3D and DirectSound. The 3D draws at the screen's native resolution with widescreen, the sound
has no DirectSound crackle, Alt-Tab comes back clean, and the engine's hard limits (physics objects,
textures, the texture table) are lifted. `race.exe` / `race.bin` aren't changed, and it works on
v1.0, v1.1 and the community 1.2.4–1.2.6 builds.

Install or remove it from the desktop app's **Modern engine** panel, or:

```bash
python -m vrmod.cli modern-engine "C:\path\to\Viper Racing\Data"            # install (everything on)
python -m vrmod.cli modern-engine "C:\path\to\Viper Racing\Data" --remove
```

The DLLs are bundled in `vrmod/assets/modern_engine/`; `scripts/update_modern_engine.py` refreshes
them from a viper-racing-port build and records the commit in `SOURCE.txt`.
